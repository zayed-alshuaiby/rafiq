# رفيق — دليل الرفع والتشغيل

## محتويات المجلد
| الملف | الوظيفة |
|---|---|
| index.html | الموقع كاملًا في ملف واحد. هذا الملف الوحيد الضروري للتشغيل |
| engine.js | محرك القواعد السريرية (نفس الكود الموجود داخل index.html) للمراجعة |
| run_tests.js | تشغيل الـ 28 اختبار: node run_tests.js |
| TECHNICAL.md | التوثيق التقني بالإنجليزي: يُرفق مع التسليم في المسابقة |

## الطريقة الموصى بها: GitHub Pages (مجاني)
تعطيك رابط للموقع + رابط للكود في نفس المكان، والحكام عادة يطلبون الاثنين.
1. أنشئ حسابًا على github.com.
2. اضغط New repository، سمّه rafiq، واختر Public.
3. اضغط uploading an existing file، واسحب كل ملفات هذا المجلد، ثم Commit changes.
4. ادخل Settings ثم Pages، واختر Deploy from a branch، والفرع main والمجلد root، ثم Save.
5. بعد دقيقة أو دقيقتين يظهر الرابط بالشكل: https://اسم-حسابك.github.io/rafiq/

## بدائل
- Netlify Drop أو Cloudflare Pages: اسحب المجلد في المتصفح وتحصل على رابط فورًا.
- Azure Static Web Apps: مناسب لاحقًا لأن Microsoft شريك في المسابقة.
- أي استضافة عادية: ارفع index.html فقط.

## لاختبار التعديلات
- أي تعديل على القواعد يكون في engine.js، ثم شغّل node run_tests.js للتأكد أن كل الاختبارات تنجح، ثم انسخ الكود داخل index.html.
- صفحة الاختبارات داخل الموقع: أضف ‎#tests‎ في آخر الرابط. وصفحة القواعد: ‎#rules‎

## قبل فتحه للجمهور (مهم)
الكتالوج نفسه ينص أن القواعد مسودة ولا تُعتمد للاستخدام الفعلي إلا بعد توقيع الطبيب. للمسابقة يكفي كنموذج تجريبي، والشريط العلوي في الموقع يوضح ذلك.
